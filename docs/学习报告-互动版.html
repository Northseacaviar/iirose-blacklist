三层缓存 + 一层版本语义 —— 一次真实发版踩坑的解剖（iirose 拉黑插件 · 2026-09-25）

这轮我做了一件小事：给插件加一个「加载器」，让朋友以后不用再手动更新。

结果在"改完到底有没有生效"这件事上连踩三坑。三个坑都不是代码写错 —— 全是交付链路的问题：浏览器缓存、CDN 缓存、以及地址解析到哪个版本。这篇就是把它们拆开给你看：每一层负责什么、我用什么证据确认它、以及下次你该怎么按顺序排查。

二、四层骨架：一次请求会碰到谁

你在浏览器里看到"旧版"，可能卡在四个完全不同的环节。它们长得像"缓存没清"，但病因、证据、解法都不一样。

点每一层展开：左边是它负责什么，右边是这次抓到的真实证据。

1浏览器强缓存 —— 我本机这份副本展开

它负责：把文件存在你电脑上，期限内根本不发请求。这是"刷新了也没用"的第一嫌疑人。

真实证据（curl -sI 拉的响应头）：

Cache-Control: public, max-age=604800, s-maxage=43200

max-age=604800 = 7 天。地址不变的话，浏览器七天不联网问一次。

解法：换 URL（loader 的 ?t=时间戳、手动的 ?v=2）或强刷 Ctrl+F5（手机用无痕）。

2CDN 边缘缓存 —— jsdelivr 机房那份展开

它负责：机房离你近，先给你一份；源站按 s-maxage 决定这份能放多久。

真实证据：

s-maxage=43200   → 12 小时
Age: 1862        → 这份副本已经在边缘放了 31 分钟

要点：浏览器那份缓存（7 天）比 CDN 这份（12 小时）久得多 —— 所以先卡住你的是浏览器，不是 CDN。

3版本解析 —— 这个地址取的是哪个版本展开

它负责：同一份文件，地址写法不同，取的版本不同。这一层最容易被忽略，因为它不是"缓存"，而是"我问的是谁"。

地址写法取到的是
.../iirose-blacklist/loader.js（无 ref）最新 tag 的快照（不是 main 分支！）
...@main/loader.jsmain 分支当前内容
...@v0.2.3/loader.js钉死在那个 tag，永不变化

真实证据（响应头直接写明解析结果）：

X-JSD-Version: 0.2.3
X-JSD-Version-Type: version

推论：不打 tag，默认地址就不动；新加的文件在默认地址上还会 404（这次就是这么撞上的）。

4注入地址本身 —— 站点里存的那一行展开

它负责：站点把自定义 JS 的地址存在 extJs 里，每次页面加载按这些地址去拉脚本。

要点：地址没变 → 浏览器按第一层规则直接读本地副本，你的"我更新了"它完全不知道。所以老用法（直连主脚本）每次更新都必须重新粘一遍。

解法：注入 loader —— 它每次用带时间戳的新地址去拉主脚本，第 1、4 层同时绕开。

八、坑卡片：这轮真正值钱的四条

坑 1 · 新文件在默认地址上 404

我新建了 loader.js，默认地址取不到它，@main 却能取到。根因是无 ref 地址解析到"最新 tag 的快照"，而那个 tag 是在我新建文件之前打的。

教训：发版必须打 tag —— tag 不只是标记，它是默认地址的内容来源。

坑 2 · 清了缓存还是旧版

purge 请求返回的响应体是空的（直连时），我没当回事；结果默认地址几十分钟都停在上一版。

教训：purge 必须走代理，而且刷完要回查解析到的版本（X-JSD-Version），不能只看"没报错"。

坑 3 · 对照实验只能排除，不能确诊

我用 curl 连发请求，@ref 路径一片 404；拿公共仓库对照也是 404 → 我写成"jsdelivr 的 @ref 全局坏了"。后来浏览器打开同一地址是 200 —— 真相是我的请求被限流。

教训：对照实验排除的是"我的东西坏了"；要确定病因，必须换第二条独立通道再验一次（换浏览器/换网络）。

坑 4 · 成本里 98% 是缓存读，别被"近亿 token"吓到

每轮都要带上长上下文，命中缓存的部分单价远低于新输入；真正花钱的是新输入与输出。

教训：报成本必须带口径 —— 估算非账单、推理 token 别与输出相加、缓存读占大头说明复用率高。

十、自测：现在你能自己判断了吗

第一次答错只说「再试一次」，不揭晓；第二次答错才给讲解。

收尾：下次先问自己什么

  • 他说"还是旧版" → 先问：你注的是 loader 还是直连地址？直连地址里带 ?v= 吗？
  • 我改了、也推了，但地址上是旧版 → 打 tag 了吗？打完 tag 等过那几十秒吗？（默认地址有分钟级延迟）
  • purge 说完成了 → 回查 X-JSD-Version，别看"没报错"。
  • 我要下结论"是平台坏了" → 先问：这是现象、排除还是确诊？确诊需要第二条独立通道。
